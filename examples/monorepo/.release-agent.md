# .release-agent.md — Monorepo example

Tagline reads this file from the root of your repo to learn how you release. Every section is optional; missing values fall back to sensible defaults documented in [`docs/configuration.md`](../../docs/configuration.md).

This example targets a **monorepo** (pnpm workspaces / Turborepo / Nx / Lerna / npm-or-yarn workspaces). Tagline auto-detects which one — you don't declare it.

## Channels

Each branch is a release channel. A merge into a channel branch opens that
channel's own release issue and ships versions with its suffix (`stable` →
clean, others → `-suffix.N`). In a monorepo, channels apply **per package**:
each package gets its own per-channel counter and tag (e.g.
`@acme/api@0.2.0-alpha.1`), anchored to that package's last stable release.

- main: stable
- staging: rc
- development: alpha

## Release notes style

Keep release notes concise and audience-friendly. Lead with the headline change in plain language; leave the technical changelog for the second half. Group related package bumps together in the summary when they tell one story.

## Custom context

This is a monorepo: every package ships with its own version, its own tag (`@scope/name@version` for scoped packages, `name@version` otherwise), and its own `CHANGELOG.md`. A release event can include any subset of the workspace's packages — only packages with attributed PRs get bumped. The `database` package is intentionally conservative; flag breaking changes prominently when it bumps.
