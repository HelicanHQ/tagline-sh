## Release notes style

Keep release notes concise and audience-friendly. Lead with the headline change in plain language; leave the technical changelog for the second half. Group related package bumps together in the summary when they tell one story.

## Custom context

This is a monorepo: every package ships with its own version, its own tag (`@scope/name@version` for scoped packages, `name@version` otherwise), and its own `CHANGELOG.md`. A release event can include any subset of the workspace's packages — only packages with attributed PRs get bumped. The `database` package is intentionally conservative; flag breaking changes prominently when it bumps.
